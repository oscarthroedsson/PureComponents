Label and control. Every other part is optional and the field still looks finished.

Label → hint → control → message. DOM order decides placement; this file sets no order. aria-describedby lists both ids — CSS cannot write that, so it is the consumer's markup.

Both fields carry a message. The first is valid, so the row is reserved but hidden — and hidden with visibility, so it is out of the accessibility tree too. The second is marked aria-invalid="true". Neither one moves when the state changes: the two controls sit at exactly the same height.

No aria-invalid here — required and type="email" do it. Type something wrong and tab out: :user-invalid fires only after you have interacted, which is why :invalid is not used. It would paint this red on page load, before you touched it.

The size class goes on the field, and the label, hint, control and message all follow. Nothing is written twice — the field rewrites one inherited variable.

The field reads the control's own state — no class to remember.
