Taken over with appearance: none, which is what buys the track, the shapes and the sizes. The cost is the fill: once the control is ours, Chromium offers no pseudo-element for the filled part, so the track is painted with a gradient that stops at --range-value. That variable does not update itself — the library ships no JavaScript. Left alone the fill sits at 50% while the thumb still moves, works and submits; see the next section for the one line that makes it follow. Always set min and max — without them the range is 0–100 whatever the numbers on screen say, and the announced value is wrong.

One line of consumer JavaScript. The library cannot ship it — see AGENTS.md §1 — but without it the fill is decoration that stands still. The control is correct either way; only the paint needs the script.

Neutral by default, so a slider does not shout in a form full of quiet controls. primary puts the brand green on the line and on the thumb.

zoom, because nothing else reaches a native control — font-size does nothing to a range, and block-size only makes the box taller while the track stays where it was. zoom scales the whole thing, track and thumb included, and it changes the layout box so the form reflows around it. transform: scale would resize the picture and let the slider spill out of its column.

One class shapes both surfaces: the capsule and the fill inside it. smooth gives the fill a tighter radius than the capsule, because the fill is half the height and the same radius would read as a pill there.

A range is announced as a slider with a number. If the number means something — kronor, minutes, a percentage — say so with aria-valuetext; CSS cannot. And never make a slider the only way to enter a value that has to be exact: pair it with a number field when precision matters.
