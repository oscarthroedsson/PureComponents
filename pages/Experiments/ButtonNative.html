Inside a form, type defaults to submit. A button meant to do something else will submit the form and navigate away. This is the single most common native-button mistake, and the library's docs never mention it. Try both.

Native disabled removes the button from the tab order entirely — which also hides the reason it is disabled from keyboard and screen reader users. aria-disabled="true" keeps it focusable and announced, but does not block activation; that is on you. Tab through both rows to feel the difference.

name and value tell the server which button was pressed. formaction, formmethod and formnovalidate let a single button override the form it belongs to, and form="id" lets a button live outside the form it submits. No hidden inputs, no click handlers.

The Invoker Commands API. command="show-modal" opens a <dialog>, command="close" closes it. Focus moves into the dialog on open and back to the invoking button on close — measured, not assumed. Baseline since Safari 26.2 (Dec 2025). This replaced 25 inline onclick handlers on the Dialog page.

popovertarget gives light dismiss, Escape handling, top-layer stacking and an implicit aria-expanded relationship for free. CSS anchor positioning places it against the trigger, with position-try-fallbacks flipping it when it would overflow — the job a tooltip library used to do. Both are Baseline.

interestfor shows the target when the user hovers, focuses, or long-presses — with the platform's own delays and the right aria-describedby wiring. popover="hint" marks it as a tooltip that does not close other popovers. Chrome 133+ and Firefox 149+; Safari does not support it yet, so this needs the current role="tooltip" approach as a fallback.

HTML has no toggle button. aria-pressed is the correct answer, but keeping it in sync genuinely requires script — this is where the library's no-JS rule actually runs out. A <input type="checkbox"> styled as a button is the CSS-only alternative, at the cost of different semantics.

button.css styles &.btn[iconOnly]. That attribute is not native, not valid HTML, and conveys nothing to assistive technology. The native answer to "this button has only an icon" is that it needs an accessible name — and CSS can detect the shape itself with :has(), no invented attribute required.
