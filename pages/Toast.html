Two things. Write the container once — it owns the placement, covers the viewport, ignores the pointer and takes up no space while it is empty, so it can sit anywhere in the markup. Then call Toast.append() with the attributes you want. Nothing else is needed: no wrapper markup, no setup call, no container built from JavaScript.

Everything append() is not told falls back to Toast.defaults: intent: "info", size: "md", duration: 6000, dismissible: true, icon: true, swipeable: true. Assigning to Toast.defaults moves them for the whole page.

role is derived when it is not given: error and warning interrupt with role="alert", everything else announces politely with role="status".

Toast composes Alert, so Alert intents are reused directly.

Toast delegates its visual size to Alert.

A page with Toasts in more than one place writes one container per place, and the second argument picks which one — an element, or a selector for it. Without it, the first .toast-container in the document is used.

Layout belongs to the container, not to the Toast. data-layout="list" shows every Toast in full, data-layout="stacked" overlaps them while idle with the newest in front, and expands to a list on hover or keyboard focus. Press either button a few times to build a pile.

Press a Toast and drag it towards the edge its container sits at, and it goes. The direction is read from the container: right for a right-hand container, left for a left-hand one, and for a centered one the way out is vertical — up from the top, down from the bottom — plus right. Dragging the other way resists and springs back, and a drag along an axis the container does not use is ignored so the page keeps scrolling.

duration is the countdown in milliseconds and defaults to six seconds; duration: 0 keeps the Toast until it is closed. The countdown pauses while the pointer is over the Toast or the keyboard is inside it. dismissible: false removes the close button.

append() hands back the Toast, so it can also be closed from wherever it was opened: const toast = Toast.append({ … }); toast.remove();

The container constrains the width through --toast-max-width while Alert handles wrapping and internal layout.

This is what createToast() builds for you — a placement and motion wrapper around an Alert. Worth reading if you render your own Toasts instead of calling append(): match this markup and the stylesheet does the rest.
