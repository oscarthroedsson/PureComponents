Two things turn it on: the class opts in, aria-busy="true" is the state. Nothing is painted over — the element steps back and a diagonal glow travels across it, so the reader can still see what is loading.

Class names

Class Type Description
loading Component Goes on the element that is waiting. Paints nothing on its own.

State

Attribute Description
aria-busy="true" Turns the effect on, and is what assistive technology reads.
disabled / aria-disabled="true" Not loading's to add. CSS cannot stop input — if the control must not be used while it waits, say so on the control.

Variables

Variable Default What it moves
--loading-opacity 0.55 How far the element steps back.
--loading-glow rgb(255 255 255 / 0.6) The travelling highlight. Light on purpose — a dark band reads as a smear, not as a glow.
--loading-angle 100deg The tilt of the glow.
--loading-duration 1.4s One pass across the element.

The same two lines on three different components. None of them knows anything about loading.

The glow lightens, so it needs something to lighten. A tinted panel carries it; the white one beside it has nothing above white to reach, and shows only the dim. Content that is not there yet wants a skeleton — a grey base with its own sweep — which is a different thing from a component that is working.

Set them anywhere above the element. Nothing here needs a new class. The buttons below are deliberately not disabled: a disabled control carries its own dim from button.css, and that one wins over --loading-opacity.
