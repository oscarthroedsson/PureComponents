An accordion is a group of Collapsible panels that reads as one block. This file adds only what appears when panels stand next to each other: the shared frame, the dividers, the spacing. Padding, the marker, the animation and the focus ring all stay in collapsible.css — nothing here repeats them.

The exclusive behaviour is not in this class. Give the panels the same native name and opening one closes the rest. Leave name off and several stand open at once. The look is identical either way, which is why there is one class and not two: the difference belongs to the markup.

Class names

Class Type Description
accordion Component The group. Goes on the wrapper.
collapsible Required On each <details> inside. From collapsible.css.
sm Size On the group. Handed down to every panel.
md Size Default.
lg Size
sharp Shape Square corners.
smooth Shape Default corner.
rounded Shape The widest corner.
separate Variant The panels stay apart as individual cards instead of joining into one block.

Markup the library cannot supply

Attribute Goes on Description
name="group" each <details> Native, and the only thing that makes the group exclusive. Same name, same set. The browser closes the others; no script is involved.
open one <details> Which panel is showing when the page loads. In a named group, only one may carry it.

Variables

Variable Default What it moves
--accordion-radius var(--radius-md) The block's corner. Size and shape classes both replace it.
--accordion-border-width 1px The frame, and the dividers between rows.
--accordion-border-color var(--color-neutral-300) The same, in colour.
--accordion-gap var(--spacing-50) Space between panels. Only separate uses it.

Everything else is tuned through the panels' own variables — see Collapsible. That is how this file works internally too: it sets --collapsible-border-width and --collapsible-radius on its children rather than restyling them, so the two files never fight over the same property.

Three panels, one name. Open the second and the first closes itself — that is the browser, not us.

The same class with no name. Nothing else changes, and nothing in the CSS knows the difference — the exclusivity lives entirely in the markup.

separate drops the shared frame and spaces the panels out, so each one is its own card. The right look when the questions have nothing to do with each other.

The size goes on the group and is handed to every panel, so it is written once instead of once per row. md is the default.

sharp, smooth, rounded. The corner belongs to the block; the panels inside are square and let the group clip them.

Everything a single panel can do still works inside a group, because the group never touches it. Here every row takes a leading marker turning 90°.

Note where the variables go: on each <details>, not on the wrapper. A component declares its variables on itself, and a declaration on the element beats an inherited one — so an inline style on the group would be ignored. From your own stylesheet you can reach them in one rule, because a selector beats a declaration: .pu-accordion > .pu-collapsible { … }. That is exactly how accordion.css hands down the size.

On a long page, put a heading in each <summary>. The spec allows one heading element there, and it lets screen reader users move between the questions by heading instead of tabbing through all of them. This is the one thing worth borrowing from the ARIA APG's accordion pattern.

The group is presentation — every guarantee lives in the panels. Two things not to do: do not add aria-expanded to a <summary> (the browser already reports it, and an explicit one would lie), and do not reach for role="tablist". An accordion is not a tab set: its panels stack, they are all in the Tab sequence, and more than one can be open. Those roles would promise arrow-key navigation that does not exist here. Tab through the set below — Enter and Space open a row, which is the whole keyboard contract the APG asks for.
