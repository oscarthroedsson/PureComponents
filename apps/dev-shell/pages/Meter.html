This is the part of <meter> that surprises people. The browser picks one of three states from low, high and optimum — and where optimum sits decides which region is which.

With optimum between low and high, the middle is good and both outer regions are suboptimum. The poor colour never appears, no matter how far out the value goes. That is the case below.

To get the third colour, optimum has to sit outside low and high. A battery: full is best, so optimum goes above high. Now high values are good, the middle is suboptimum, and below low is poor.

With no low, high or optimum, the value is always in the optimum region, so the gauge is a single colour. The native element already exposes value, min and max to assistive technology — no aria-valuenow needed.

Meter is a gauge, not a task. Use Progress for how far something has got, Meter for how full something is.

data-color takes a design token — primary (default), success, error, warning, info — and sets the optimum colour. The groove behind the bar stays neutral: the bar changes colour as the value crosses a threshold, so a tinted groove would be stuck on the optimum colour and sit there in green behind a yellow bar. Pass --meter-track-color a tint if a gauge only ever uses one colour.

--meter-color takes anything CSS understands and beats data-color. --meter-suboptimum-color and --meter-poor-color recolour the other two states, and --meter-track-color overrides the groove on its own. All plain markup, no JavaScript.
