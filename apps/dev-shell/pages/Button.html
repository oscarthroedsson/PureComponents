Every key the component answers to, grouped by category. .pu-btn is a look, not an element — it sits on <button> for an action and on <a> for a destination.

KeyTypeDescription
.pu-btnKeyThe key. Nothing below applies without it — the whole component hangs off this one class, so a consumer's own CSS is never touched by merely linking the stylesheet. Goes on <button> or <a>.
btn-smSizeSmaller type and radius.
btn-mdSizeThe default. The base already gives this.
btn-lgSizeLarger type and radius.
btn-sharpShapeNo radius.
btn-smoothShapeThe same radius as btn-md.
btn-roundedShapeFully round on the short side.
(none)EmphasisFilled, in the primary colour. The default.
btn-emphasisedEmphasisThe secondary colour as the fill.
btn-secondaryEmphasisThe secondary colour, with a hover of its own.
btn-outlineEmphasisNo fill. The border and the label carry the primary colour.
btn-tertiaryEmphasisNo fill, underlined. Hover thickens the underline, never fills the ground.
btn-ghostEmphasisNo fill. A neutral ground on hover.
data-intent="destructive"IntentA destructive action. Red fill and white text, whatever the emphasis class.
data-icon-only="true"StateSquare. Requires aria-label.
aria-pressed="true"StateA toggle button in its pressed state.
disabledStateDimmed, and takes no pointer events. Only on <button>.
aria-disabled="true"StateThe same look on <a>, which can never be :disabled.
:hoverStateThe fill goes 10 % darker.
:activeStateShrinks to 95 %.

This file declares no --btn-* variables, so the Variables row is empty — the component reads --color-primary and friends straight from main.css. The only Key is the key itself — a button has no named children. No Layout or Animations either; it is one box that does not move.

The key and a size. Nothing else is needed, and btn-md is what the base already gives.

Three sizes. They move type and radius together, so a small button is not just a short one.

type is what separates these, not the class. A <button> inside a form submits unless told otherwise, so the cancel button needs type="button" or it will submit too.

Shape. btn-smooth is the middle one and matches what btn-md already gives.

How loudly the button asks. One filled primary per view is the rule of thumb — everything beside it steps down. data-intent="destructive" is not an emphasis level but a meaning, and can sit on any of them.

Every button carries a border, always. A filled one paints it in its own surface colour, so it is invisible but occupies space — which is why a filled and an btn-outline button placed side by side are exactly the same height and width. Without it, adding an outline to a row would shift everything beside it by two pixels.

Hover and active answer the pointer on their own. Disabled is the one that needs care: disabled is native and only a <button> can carry it, so an <a> uses aria-disabled="true" to reach the same look. Keyboard focus comes from main.css and this file never draws its own.

A toggle reports itself through aria-pressed, which a screen reader announces as pressed or not pressed. The library ships no JavaScript, so flipping the attribute is the consumer's job — the button in this pane's header does it here, rather than putting an onclick in markup nobody should copy.

This file declares no --btn-* variables of its own, so there is no per-component tuning surface to set. What it reads instead are the shared tokens, and those can be set on the element or on any ancestor. Edit the values in the pane and watch both buttons follow.

What follows is Button's own, and belongs to no shared category. A page is free to name these sections whatever describes them — the fixed vocabulary above ends here.

An icon beside a label is decoration and takes aria-hidden="true"; the label is what is announced. The base sets the gap, so nothing needs spacing by hand.

data-icon-only="true" squares the box. There is no label left to announce, so aria-label stops being good practice and becomes the only thing making the button usable.

Several buttons for one decision. The emphasis order carries which one is the expected answer, and the destructive one is set apart by meaning rather than by being loudest.
