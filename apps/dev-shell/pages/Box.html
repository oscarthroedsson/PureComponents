API

KeyTypeDescription
.pu-box Key The key. Padding on all four sides and a corner. It sets no display, no width, no background and no border.
box-none Size No padding. Keeps the corner.
box-xs Size Extra-tight padding.
box-sm Size Tighter padding.
box-md Size The default. The base already gives this.
box-lg Size Roomier padding.
box-xl Size Extra-roomy padding.
box-sharp Shape Square corners.
box-smooth Shape The same corner box-md already gives.
box-rounded Shape Larger corner.
box-x Layout Padding on the inline sides only.
box-y Layout Padding on the block sides only.
box-top Layout Padding at the top only.
box-bottom Layout Padding at the bottom only.
box-start Layout Padding at the leading edge only. Left in a left-to-right page.
box-end Layout Padding at the trailing edge only.
--box-padding Variables How much padding. Any length, not only the named sizes.
--box-radius Variables The corner.
--box-padding-block-start Variables One side on its own. Same for -block-end, -inline-start and -inline-end.

The key alone is box-md on all four sides. The background here is inline, not the component — a box paints nothing, so give it a surface when you want its corner to show.

Six, because box-none is a real answer: no padding, corner kept.

The corner only shows against a surface, a border, or clipped content.

The sizes are four points on a scale, not the whole scale. --box-padding takes any length, and the side classes go on working against whatever it is set to.

Other

Related layout

A Box can carry the attributes documented by Layout, and its direct children can carry the attributes documented by Behavior. Those separate modules own those APIs.

A side class narrows the padding to the sides it names. start and end rather than left and right, so a box means the same thing in a right-to-left page.

Side classes add up. Two of them give you both, so box-top box-bottom is the same box as box-y, and box-x box-y is the same as neither.

One key per element

A box goes on its own element. It writes padding and border-radius, and so does almost every component in the library — put both on one element and the two fight over the same properties, with file order deciding the winner.

Wrap instead:

<div class="pu-box box-lg">
  <article class="pu-card card-md">…</article>
</div>
