Both bindings are correct. Wrapping the input in the label needs no ids and cannot come apart; for survives the box moving. Either way the label is part of the target — the box alone is smaller than the 24×24 that WCAG 2.2 asks for, and the two together clear it.

Checked changes the fill and puts a mark in the box — colour is never the only signal. Indeterminate is a different shape, not a different shade, and it is set from script only: there is no attribute for it, and it means "some of the children are checked", never a third value a user can click to.

The box is measured in em, so it follows the text it sits beside — and a size class on the .pu-form or the .pu-fieldset reaches it without this file knowing they exist.

checkbox-sharp and checkbox-smooth, and that is the whole list. There is no checkbox-rounded: round means "pick one" and square means "pick as many as you like", and that is the only thing telling a checkbox from a radio before anyone has read the label. Leaving the class out is not what enforces it — the radius is capped at a quarter of the box, so a checkbox stays square whatever arrives on the channel. radio.css refuses the same thing from the other side.

A single checkbox that must be ticked is a .pu-field like any other: hint above, message below, and the message row reserved whether or not it shows so the page does not jump. The box turns too — the border alone is not allowed to carry it, which is why the message appears with it. For a group, the message belongs to the <fieldset> and is revealed by aria-invalid on the group: :user-invalid fires on a control, never on the group around it.

More than one checkbox answering one question is a <fieldset> with a <legend>. The legend is the question; without it a screen reader reads five unrelated options.
