A radio without a name is not a radio: the name is what groups them, what makes only one checkable, and what makes the arrow keys move between them. The group belongs in a <fieldset> — the legend is the question, and without it a screen reader reads a list of answers to nothing. Tab into the group and use ↑ ↓: one tab stop for the whole set, not one per option.

Checked fills the circle and puts a dot in it — colour is never the only signal. There is no indeterminate: a radio has two states, and a checked one cannot be unchecked without picking another. That is why a default should only be pre-checked when it is a real default the user would have picked anyway.

Measured in em, so the circle follows the text beside it and a size class on the .pu-form or the .pu-fieldset reaches it.

The constraint belongs to the group, not to any one button — so a required group with nothing picked makes every button in it match :user-invalid, and the whole set turns. That is right: the question is unanswered, not one option. The message is a .pu-field-error placed directly in the <fieldset> and revealed by aria-invalid on it, because :user-invalid never fires on a group.

Round means pick one; square means pick as many as you like. That is the only thing telling the two controls apart before a user has read or clicked anything — the label does not say it and neither does the mark. So .pu-radio takes no shape class and reads no --form-radius: a radio in a .pu-form.sharp stays round. A square radio is a checkbox that silently throws away the last answer.
