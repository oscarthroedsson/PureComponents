The key alone is already md and smooth. A pill is the interactive counterpart to a badge — where a badge annotates something else, a pill is its own object.

The key is a look, not an element. Which element it sits on decides what the pill is: button for an action, a for a destination, label for a selection, span or li for a tag that is not itself a control.

Three sizes: sm, md, lg. Same scale as .pu-btn, because that is what a pill is — a small button. Heights land at 24.8 / 28.6 / 32.4px, so every size clears the 24px target floor.

sharp, smooth, rounded. smooth is what the key alone gives.

The default is a light neutral box. outline drops the fill and keeps the border; ghost drops both, for a dense row where the boxes would fight each other. Each variant owns its own hover, so hovering an outline pill does not snap it back to the neutral fill.

A label with the input inside it. :has(:checked) paints what the checkbox already reports — the control keeps its own role, Tab and Space work because nothing was reconstructed, and the library still ships no JavaScript. Try it with the keyboard.

The same pattern with radios instead of checkboxes. One name, one choice — and arrow-key navigation between them, which the browser gives for free.

A button with aria-pressed. Same painted state as the label form, for a control that toggles a view rather than submitting a value with a form.

The selected pill fills and shows a marker, so the state survives a colour-blind reader and a greyscale print. The marker occupies its space at both states and only its opacity changes — picking a filter does not resize it, so the row never reflows under the pointer. It appears only where the pill is actually selectable; a plain action pill never grows one.

A removable tag is two controls, never one. The tag is the text; the remove control is a separate button with its own accessible name. Written as a single <button aria-label="Remove JavaScript"> the tag stops existing as an object and the whole pill becomes destructive — which is also why the key sits on a span here: a button cannot contain a button.

These are badges, not pills. Nothing here responds to the pointer and nothing contains a control, and a pill is by definition the interactive counterpart to a badge — so the key is .pu-badge. The list part still matters: ul with the key on each li gives a screen reader the count and the position — "list, 4 items" — which a row of loose spans does not.

An icon is sized from the one font-size, so it follows every size class without a second rule. Decorative ones get aria-hidden="true".

A button can be :disabled; an a never can, so it carries aria-disabled="true" instead. Both are styled.

The section that keeps the old bug visible. A pill is inline-flex, not inline: on an inline box height and padding-block paint without reserving room in the line, and the pill lays itself over the line above. The dev shell hides it — every stage is a flex container, which blockifies whatever is on it.

Pill and badge borrow the same height floor and the same em-derived box on purpose, so the pair reads as one library when they share a row. The difference you should see is what they are — the badge does not answer the pointer.

Every measurement and colour in the file is a variable on the key block, so a consumer tunes a pill inline rather than writing a rule to fight ours. Even the selection marker is one — it is content, not a colour.
