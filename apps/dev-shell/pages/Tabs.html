Every key the component answers to. .pu-tabs has two markups with one look. On a <fieldset>, each tab is a <label> around a radio: the browser owns selection and arrow keys, and CSS shows the panel in the same position as the checked tab. On a <div>, each tab is a <button role="tab">: a script owns aria-selected, the keyboard and each panel's hidden, and PureUI only paints it.

tabs-content is optional. A header on its own is a view switcher — the choice changes something elsewhere on the page. Screen readers announce the radio form as radio buttons, not tabs; use the script-driven form where real tab semantics are needed.

KeyTypeDescription
.pu-tabsKeyThe key. Goes on <fieldset> for the radio form and on <div> for script-driven tabs.
tabs-legendLayoutThe radio group's name. Read by assistive technology, not painted.
tabs-headerLayoutThe box the tabs sit in. As wide as its tabs.
tabs-tabLayoutOne tab. A <label> around a radio, or a <button role="tab">.
tabs-inputLayoutThe native radio inside a label tab. Owns selection, focus and arrow keys.
tabs-contentLayoutOptional. Holds the panels. Leave it out to use the header as a view switcher.
tabs-panelLayoutOne panel. Without JavaScript, panel n shows when tab n is checked, up to ten.
tabs-smSizeSmaller type, padding and radius.
tabs-mdSizeThe default. The base already gives this.
tabs-lgSizeLarger type, padding and radius.
tabs-sharpShapeNo radius.
tabs-smoothShapeThe default corner.
tabs-roundedShapePill-shaped header and tabs. Panels keep the large corner.
:checkedStateOn the radio. Its tab gets the raised selected look.
aria-selected="true"StateThe same look on a role="tab" button.
disabledStateOn the radio or the button. Muted and not selectable.
aria-disabled="true"StateThe same look where disabled cannot be used.
hiddenStateOn a panel in the script-driven form. The script sets it.
data-icon-only="true"StateA square tab. The radio or button needs aria-label.
:hoverStateAn unselected tab gets a faint ground.
--tabs-radiusVariablesThe header corner. Tabs and panels follow it.
--tabs-gapVariablesSpace between the header and the panels.
--tabs-header-backgroundVariablesThe header box surface.
--tabs-header-paddingVariablesSpace between the header edge and the tabs.
--tabs-tab-selected-backgroundVariablesThe selected tab surface.
--tabs-tab-selected-shadowVariablesThe selected tab lift.
--tabs-panel-backgroundVariablesThe panel surface.
--tabs-panel-radiusVariablesThe panel corner, when it should differ from the header.

Tab into the group, then use the arrow keys. The browser checks the radios; CSS shows the panel in the same position.

Size moves type, padding and radius for the header, tabs and panels together. Medium is the default.

Shape sets the header corner. Tabs follow it from inside the padding; a rounded panel keeps the large corner.

Selected comes from :checked. Disabled is native on the radio, and the arrow keys skip it.

The script-driven form. The button above the preview stands in for the script: it moves aria-selected, tabindex and hidden. PureUI ships no script; the look is the same as the radio form.

No tabs-content. The header is a view switcher, and the page decides what the checked value changes. Icon-only tabs need aria-label on the radio.
