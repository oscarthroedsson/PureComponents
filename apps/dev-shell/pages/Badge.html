The key alone is already md. A label, a word, a count.

A badge is an inline box, so it sits on the text baseline and reserves its own room in the line. This section exists to keep it that way — before the rewrite the badge was display: inline and its vertical padding overlapped the line above.

Three sizes: sm, md, lg. The scale stays inside badge territory on purpose — lg is a badge you can read across a table, not a heading. One variable, --badge-font-size, and the padding follows it in em.

data-intent writes one variable, --badge-accent, and the background and border are mixed out of it. The word carries the meaning — the tint only agrees with it.

outline drops the tint and keeps the border. ghost drops both, for a dense list where the boxes would fight each other — the same meaning ghost has on .pu-btn.

sharp, smooth, rounded. smooth is the default, as everywhere else in the library. Size and shape are independent.

An icon is sized from the badge's own font size, so it follows every size class. A bare run of text becomes an anonymous flex item, so gap spaces the two without any wrapper element. Decorative icons get aria-hidden="true".

The key may sit on an <a> for a tag filter. It then gets the house focus indicator — tab into these. It may not sit on a <button>: an interactive chip is Pill.

Counts on a control, and status beside a name.

The badge repeats what the button already says, so it is hidden from assistive tech and the button carries the whole name. aria-label on the badge itself would not work — a bare <span> has no role for a name to attach to.

role="status" belongs on a container the badge sits inside, never on the badge. The badge is the value; the container is the live region.
